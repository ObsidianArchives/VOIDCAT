## ▸▸▸  EDITING PROTOCOL  ◂◂◂
 
> *How to update SCROLL efficiently. Token-aware. Batch-first.*
 
### BATCH UPDATE RULES
 
1. **Never update one field at a time** — accumulate changes across the session, then update ALL affected sections in ONE edit pass.
2. **Read the full file before any edit** — SCROLL is ~450 lines. Always read it completely before editing so you know what's stale, what's current, and what cross-sections need updating together.
3. **Update in dependency order:**
   - FIRST: Dashboard (line counts, progress bars, phase status)
   - THEN: Work Log (new entries)
   - THEN: File Status (reflect changes)
   - THEN: Architect Log (chronicle entries)
   - THEN: Session Plan (mark phases complete, add new)
   - THEN: Done (archive completed items)
   - LAST: Directory Tree (if file structure changed)
4. **Line counts are source of truth** — always run actual line count before updating any number. Never guess.
5. **Version bump on material change** — if a file's content changed meaningfully, bump its version in File Status table. Micro-edits (typos) don't count.
### SESSION STATE TRACKING
 
6. **Start every session by reading SCROLL.md first** — single source of truth for what's done, pending, blocked.
7. **End every session by updating SCROLL.md** — log what was done, update progress bars, mark phases, add architect entries. The scroll must always reflect reality.
8. **Use /scratch for mid-session notes** — don't edit formal sections while working. Dump raw notes in /scratch, then batch-update at session end.
### TOKEN-EFFICIENT PROCESSING
 
9. **Use glob/grep for targeted reads** — check specific sections with grep patterns rather than reading the full file.
10. **Batch file reads** — read multiple files in parallel for line counts or version tags.
11. **One edit call per section** — group all changes to a single section into one edit call. Don't make 5 small edits to File Status — make 1 edit with all 5 changes.
12. **Skip unchanged sections** — if only Dashboard and File Status changed, don't touch Bond Tracker, Mutation Tracker, or Retrospective.
